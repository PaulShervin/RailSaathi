# Station navigation (indoor routing)

The station-navigation backend from `Navigation_exp/railsathi-navigation` is merged into the main
RailSaathi backend. It runs in the same FastAPI server (port 8000), so no separate service is needed.

| Part | Location |
|---|---|
| Routing engine, validator, graph builder, stores (unchanged logic) | `backend/app/navigation/services/` |
| Pydantic models | `backend/app/navigation/models.py` |
| API routes | `backend/app/navigation/routers/` |
| Settings (`RAILSATHI_*`, read via `app/config.py`) | `backend/app/navigation/config.py` |
| Station data (Chennai Central plan, graph, metadata, info) | `backend/data/stations/chennai_central/` |
| National helplines (sourced, checked 2026-10-10) | `backend/data/common/helplines_india.json` |
| Original tests (61, all passing) | `backend/tests/navigation/` |
| Mobile screen | `frontend/src/mobile/screens/StationNavigation.tsx` |
| Frontend client, hook, map | `frontend/src/navigation/` |

## API (same paths as the original module)

- `GET /api/stations`, `GET /api/stations/{id}`, `GET /api/stations/{id}/info`
- `POST /api/navigation/route`: Dijkstra over traced walkways, with `avoid_stairs`, `wheelchair` and `require_verified_accessibility` as hard constraints
- `POST /api/navigation/snap`
- `GET|POST|DELETE /api/stations/{id}/disruptions`: simulated closures
- `GET /data/stations/{id}/{image}`: floor-plan image
- Editor writes (`PUT /api/stations/{id}`, drafts, versions): need `X-Admin-Token`. They are disabled while `RAILSATHI_ADMIN_TOKEN` is empty.

## What the passenger sees

- **From / To:** chosen from the station's real waypoints (junctions are hidden).
- **Accessibility options:** wheelchair and avoid-stairs are pre-selected when the passenger asked for them in the planner.
- **Map:** the route is drawn on the floor plan using only the stored walkway polylines, never a straight line, with labelled start and destination markers.
- **Step-by-step:** the instructions generated by the backend.
- **Route summary:** distance and walking time, labelled as estimates from the plan scale, plus backend warnings (for example, unverified pathways).
- **Along the way:** nearby facilities, each with "Go here".
- **Simulate a closure:** closes a pathway, then reroutes. The closed pathway shows "✕ CLOSED (simulated)" and the old route is drawn dotted. "Reopen all" removes the closures.
- **Start Navigation (simulated):** a marker moves along the route and highlights the current step. It is labelled as simulated, not the passenger's real position.

## Honesty and limits

- The Chennai Central graph is hand-traced from the plan and is **pending on-site verification**. Pathway accessibility is `unknown` unless stated, and the screen says so.
- The train data (RailRadar) gives no platform number, so the screen says "Platform not provided by the train data" and never guesses one.
- Only Chennai Central (`MAS`) has a floor plan. Other stations need a blueprint traced with the teammate's editor (see `Navigation_exp/railsathi-navigation/README.md`, "Adding a new station"). Add the station-code mapping in `frontend/src/navigation/navApi.ts` (`NAV_STATION_FOR_CODE`).
- The original editor UI (`/admin/stations/{id}`) lives in `Navigation_exp/railsathi-navigation/frontend` and is not part of the mobile app.
