# Session Log 007 — Live Data Readiness & Connecting-Journey Integration Audit

- **Date**: 2026-10-10
- **Focus**: Integration audit and defects verification for RailRadar live authentication (HTTP 401 Unauthorized), connecting-train discovery service (`connecting.py`), train operating day validations, booking URL allowlisting, safe fare combinations, and production provider error isolation.

## Summary of Audit Findings & Enhancements

1. **RailRadar Live Authentication Audit**:
   - Verified official endpoint documentation at `https://railradar.in/docs` and `https://railradar.in/docs/trains-between-stations`.
   - Confirmed Base URL `https://api.railradar.in/v1`, endpoints (`GET /v1/trains/between/{from}/{to}`, `GET /v1/lookup/search/stations`, `GET /v1/trains/{number}/fare`), and dual header support (`Authorization: Bearer <KEY>` and `X-API-Key: <KEY>`).
   - Verified that the backend correctly reads `RAILRADAR_API_KEY` from `.env` as a clean 36-character string without truncation or double-prefixing.
   - Performed minimal smoke probe: upstream server returned `HTTP 401 Unauthorized` with body `{"code": "UNAUTHORIZED", "message": "Invalid API Key"}` and trace ID.
   - Identified root cause: The configured key is either unactivated, expired, or an account ID rather than an active production secret token generated from `https://railradar.in/developers`.

2. **Connecting Trains Discovery Audit & Fixes**:
   - Verified that both legs use the confirmed intermediate interchange hub.
   - Enforced operating days verification: checks `t.runs_on_days` against the specific day-of-week for both leg departure dates.
   - Full datetime layover verification: ensures `30 <= layover_minutes <= 360` across overnight and multi-day calendar rollovers.
   - Feasibility deadline verification: validates Leg 2 arrival against venue meeting deadline and last-mile travel, correctly classifying `insufficient_data` when last-mile duration is unknown.
   - Safe combined fare calculation: `total_estimated_fare` is computed only when both leg fares exist; otherwise set to `None` to prevent fabricated numbers.
   - Official booking handoffs: validated through `BookingHandoffService` and verified against domain allowlist (`www.irctc.co.in`, etc.).

3. **Production Provider Error Isolation**:
   - In `timetable.py` (`TrainSearchService.search_trains`) and `planner.py` (`JourneyPlanner.plan_journey`), when `TRAIN_DATA_PROVIDER=railradar`, provider failures (`RailRadarAuthError`, `RailRadarUnavailableError`, `RailRadarRateLimitError`) return structured `status: "provider_unavailable"` responses instead of silently switching to mock data.

4. **Test Suite Expansion**:
   - Added 8 dedicated unit & integration tests in `test_connecting_trains.py` covering valid transfers, tight layover rejection, deadline misses, missing last-mile data, safe combined fares, deduplication, and provider failure handling.
   - Full test suite: **106 / 106 automated unit & integration tests passing (100%)**.
   - Verified clean frontend build with Vite.
